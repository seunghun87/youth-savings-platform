| 항목 | dev | 현재 |

| 동기화 API 보호 | 없음 | 공유 비밀키 + 상수 시간 비교(타이밍 공격 방어) |
| 입력 검증 | 없음 | 타입·범위·화이트리스트 검증 후 통과 필드만 저장 |

**신규 파일**: `authenticateUser.js`, `requireSyncSecret.js`, `validation/userState.js`

### 리뷰에서 발견한 인증 관련 결함

- **화면 저장 경로의 사용자 ID가 하드코딩**되어 있었습니다. 플랜 화면의 적금 추가·중도해지 요청이 로그인 사용자가 아닌 고정값(`"demo-device"`)으로 나가고 있었고, 인증이 적용된 뒤로는 **해당 기능이 전부 403으로 실패하는 상태**였습니다. → 로그인 사용자 ID를 전달하도록 수정.
- **인증 만료가 화면에 드러나지 않았습니다.** 토큰이 만료되면 서버 응답 실패가 로컬 저장 데이터로 대체되어, 사용자에게는 "예전 데이터가 그대로 보이는" 상태가 됐습니다. → 세션 정리 후 로그인 화면으로 복귀하도록 수정.

## 4. 계산 정확성 — 추천·배분 로직 정합성

`dev`에는 상품 추천과 저축액 배분이 **서로 다른 규칙**으로 동작하는 문제가 있었습니다. 같은 사용자 입력에 다른 결과를 내는 구조였습니다.

| 쟁점 | dev | 현재 |
|---|---|---|
| 금리 선택 규칙 | 추천/배분이 각각 다른 구현 | 공통 모듈(`productRules.js`)로 통일 |
| 만기액 계산 기간 | 사용자 목표 기간 사용 | 실제 적용되는 상품 옵션 기간 사용 |
| 판매중단 상품 | 배분 결과에 포함됨 | 가입 가능 상품만 대상 |
| 자격 판정 기준 | 추천과 배분이 불일치 | 동일 기준 적용 |

### 핵심 결함: 기대 수령액 과대계상

배분 로직이 **기간과 무관하게 전체 최고금리**를 고른 뒤, 그 금리로 **사용자의 목표 기간 전체**에 대한 이자를 계산했습니다.

> 예: 6개월 옵션 4.2% / 12개월 옵션 3.0%인 상품에 60개월 목표를 넣으면
> → (dev) 4.2%로 60개월치 이자 계산 — **실제로는 불가능한 금액**
> → (현재) 12개월 3.0%로 12개월치 계산 — 금리와 기간이 같은 옵션에서 나옴

금리와 계산 기간을 **하나의 함수가 함께 반환**하도록 바꿔, 둘이 어긋날 수 없는 구조로 만들었습니다.

## 5. 신규 기능 — 청년정책 맞춤 추천

**사용자 조건에 맞는 청년정책을 찾아주는 기능을 새로 제공합니다.** `dev`에서는 혜택 탭이 고정된 3건을 모든 사용자에게 동일하게 보여줬습니다.

| 항목 | dev | 현재 |
|---|---|---|
| 혜택 탭 데이터 | 하드코딩 3건 | 온통청년 실데이터 (최대 50건) |
| 개인화 | 없음 (전원 동일 화면) | 나이·연소득 기준 맞춤 |
| **소득 조건 필터** | **동작 안 함** | **연소득 기준 자동 판정** |
| 자격 표시 | 없음 | 충족 / 확인 필요 / 미충족 + 사유 |
| 분류 필터 | 고정 4개 | 정책 분류 기준 동적 생성 |
| 우선순위 | 없음 | 충족 정책 상위 노출 |

### 소득 조건 필터

사용자의 연소득을 기준으로 각 정책의 지원 자격을 자동 판정합니다.

- **구조화된 소득 조건**: 정책의 소득 상한·하한과 사용자 연소득을 대조
- **자격요건 텍스트 판정**: "연소득 3,600만원 이하", "소득 5분위 이하" 같은 자유 문구에서 금액·분위를 추출해 판정
- **판정 불가 조건 구분**: 가구소득·기준중위소득처럼 개인 소득만으로 판단할 수 없는 조건은 "확인 필요"로 분류해, 잘못된 탈락 안내를 방지

판정 결과는 사유와 함께 표시됩니다.
> 예: `소득 조건 불충족 (소득상한 2,000만원 이하, 입력 3,000만원)`

### 성능·안정성 보강

- **응답 크기 제한**: 정책이 수천 건이라 전량 전송 시 응답이 수 MB에 달했습니다. 기본 50건·최대 200건으로 제한.
- **우선순위 정렬**: 충족 → 확인 필요 → 미충족 순, 같은 상태면 연령 범위가 좁은(더 특정 대상을 겨냥한) 정책을 상위 노출.
- **조회 캐시**: 요청마다 전체 정책을 DB에서 읽던 것을 캐시로 전환. 동시 요청이 몰려도 DB 조회는 1회.
- **파라미터 검증**: 나이·소득·분위 입력값의 타입과 범위를 검증. `dev`에서는 검증이 없어 잘못된 값이 그대로 판정에 들어갔습니다.

## 8. 코드 가독성

| | dev | 현재 |
|---|---|---|
| `userState.js` | 12줄 (압축) | 512줄 (정상) |

동작은 그대로 두고 구조만 복원했으며, 이를 보증하기 위해 **라우터에 실제 HTTP 요청을 보내는 테스트 13개**를 함께 작성했습니다.

이 외 정리: 미사용 컴포넌트 2개(402줄) 제거, React 훅 규칙 위반 해소, 도달 불가능한 분기 제거.
